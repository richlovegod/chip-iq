# 7729 籌碼與市值監測

**線上版**：https://richlovegod.github.io/chip-iq/

## 券商分點：資料源與坑

分點資料取自 **TPEx 興櫃買賣日報表 EMdss004**，一列 = 一天 × 一檔 × 一分點 × 一個成交價。存成每日明細、**不預先加總**，任意區間都由前端即時聚合——現行 email 報表固定在 5／10 日，是資料形態造成的限制，不是選擇。

```
https://www.tpex.org.tw/www/zh-tw/emerging/dailyDl?name=EMdss004.YYYYMMDD-C.csv
```

四個會卡住的地方：

1. **必須帶 `/www/` 前綴**。日統計頁面上列出的連結是 `/zh-tw/emerging/dailyDl?...`，直接打會 302 到 `/errors`。頁面本身有 Cloudflare 擋，但這支下載端點沒有。
2. 編碼是 **Big5**（用 `big5hkscs` 才不會掉罕用字），CRLF 換行，格式是自訂的 `TITLE`／`HEADER`／`BODY` 前綴而非標準 CSV 表頭。
3. **只涵蓋「電腦議價點選系統交易」**，不含系統外議價（那是 `EMdcs002`）。現行報表也只用這一份，不要自作主張合併，否則對不上。
4. 興櫃日報表只給**券商代號**。TWSE 兩支證券商基本資料 API 可蓋掉 99.2%，但「經紀部／自營」這類總公司層級的交易代號查不到，需併入公司自行彙整的對照表（見 `fetch_broker_lut.py` 的 `EXTRA`）。

歷史自民國 96 年起提供，可一次回補；目前站上為近一年（241 個交易日、827 家分點）。

### ⚠️ 券商代號會中途改編

用站上這一年的資料反推，期間有兩組代號整批換掉：

| 舊代號 | 最後出現 | 新代號 | 首次出現 |
|---|---|---|---|
| `592x` | 2026-01-30 | `9B2x` | 2026-02-02 |
| `815x` | 2026-04-02 | `9B1x` | 2026-04-07 |

兩件事要注意：

1. TWSE 現行券商清單只留新碼，**舊碼查不到名稱**，站上以代號顯示並加註記（`592r` 這種）。
2. **區間若跨過換碼日，同一家分點會被拆成新舊兩列**，長區間累計會低估。籌碼分析與分點追蹤在區間含舊碼時會跳出提示。

以 5／10 日窗格看不到這件事，拉長區間就會遇到 —— 現行報表同樣有這個問題。

### 分點資料驗證

以現行《生技籌碼與市值綜合日報》2026-07-21 那期為黃金樣本，`scripts/verify_broker.py` 做回歸測試：

- **當日買超合計 69,444 股** — 完全吻合
- 前十大買超／賣超分點的**淨額、成交量加權均價、佔比**逐筆一致
- 造市商（第一金自營、永豐金自營、台中銀自營）均價 0.00 為造市結構所致，非缺漏

網頁「籌碼分析」分頁底部也直接呈現同一份對帳。

> 佔比的分母是**區間單邊總成交量**（買進合計恆等於賣出合計），與現行報表定義一致。

### 計價規則

- **市值 ＝ 已發行普通股數 × 當日價格**
- 上市／上櫃取**收盤價**；興櫃取**成交均價**（興櫃是議價交易，最後成交價常是離群值，均價較能反映交易重心）
- 興櫃的**造市商成交均價顯示 0.00 屬正常結構性現象**，非資料缺漏。7729 的推薦證券商為第一金自營、永豐金自營、台中銀自營，介面上會標記為「造市」

### ⚠️ 三個會算錯市值的坑

1. **上櫃**日成交表的量／額單位是**仟股／仟元**，上市與興櫃是股／元 —— 不換算會差 1000 倍。
2. **不可用「實收資本額 ÷ 10」推算股數** —— 部分公司面額不是 10 元（例：沛爾生醫 6949、康霈 6919 為 0.5 元），會差 20 倍。一律取「已發行普通股數」欄位。
3. 興櫃歷史行情端點的 `date` **必須是完整日期** `YYYY/MM/DD`，只給年月會被無聲忽略、一律回傳當月。

## 市值正確性驗證

以現行每日報表 2026-07-21 那期作為黃金樣本逐檔對帳：

- **再生醫療 12 檔**：6 檔誤差 0.00%，10/12 在 0.5% 以內
- **生技大盤 Top 30**：市值 26/30 完全吻合；成分 29/30 重疊

剩餘落差**全部來自股數與成分、不是價格**。

兩處成分差異都源自近期的公司異動：**TLC-KY（7924）2026-06-26 才登錄興櫃**，市值 281.85 億應排第 8，靜態名單尚未納入，導致其後每一名都少算一位（7729 實際為第 68 名而非 67）；**泰宗（4169）2026-04-08 才轉上市**，股數亦有出入。本站每次執行都重抓公開資訊觀測站的「已發行普通股數」，因此不會隨時間過期。此差異建議與報表維護同仁核對後定案。

`data/peers.json` 內含完整對帳結果，網頁「同業比較」分頁底部也直接呈現。

## 更新資料

```bash
python scripts/fetch_tpex.py          # 7729 價量與市值（預設近 24 個月）
python scripts/fetch_peers.py         # 再生醫療 12 檔（預設近 12 個月）
python scripts/fetch_universe.py      # 生技全市場排名與 Top 30（約 100 個請求、1 分鐘）
python scripts/fetch_broker_lut.py    # 券商代號對照表（三來源合併）
python scripts/fetch_broker_daily.py  # 券商分點每日明細（預設回補 365 天）
python scripts/verify_broker.py       # 分點回歸測試（對 2026-07-21 黃金樣本）
```

每日更新只要跑 `fetch_broker_daily.py --days 7`——抓過的日子存在 `cache/`（一天一檔約 6KB，**進版控**），不會重複下載，換一台機器跑排程也不必重新回補。回補一整年約 250 個請求、每天 2MB，跑一次十分鐘左右。

`--days N` 只決定**這次要下載哪幾天**；輸出一律涵蓋 `cache/` 裡的所有交易日，不會因為跑 `--days 7` 就把歷史砍成 7 天。

`build_fixture.py` 產生的 `broker_fixture.json` 已不再供前端顯示，只留作對帳基準，除非黃金樣本要換一期，否則不需要重跑。

跑完後 `git add data cache && git commit && git push`，GitHub Pages 約 1 分鐘後生效。

## 排程

`.github/workflows/daily.yml`：每個交易日 UTC 09:30（台北 17:30）自動跑完上面全部腳本、跑回歸測試、commit 並發佈。回歸測試沒過就中止，不會把錯的數字推上去。也可以在 Actions 頁面手動觸發。

之所以能跑在 GitHub Actions，是因為**本站所有資料源都是公開 API、沒有任何憑證要保管**，排程不綁任何一台個人電腦。反過來說，需要帳密或內部資料的東西不要加進這個 workflow。

兩件維運上要知道的事：

- **repo 連續 60 天沒有活動，GitHub 會自動停用排程**。機器人自己推的 commit 算不算活動並不明確，請每月看一眼網頁上的「最後更新」日期。
- **repo 日後轉移給公司帳號時，Actions 會跟著走、不必改設定**，但 GitHub Pages 網址會從 `richlovegod.github.io/chip-iq` 變成 `<新帳號>.github.io/chip-iq`，已經發出去的連結會失效，要重新通知使用者。

## 本機預覽

```bash
python -m http.server 8899
```

然後開 http://localhost:8899 。

⚠️ **不要直接雙擊 `index.html`**——瀏覽器會擋 `file://` 的 fetch，整頁會是空的。一定要透過 HTTP 伺服器開啟。
